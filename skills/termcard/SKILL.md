# 术语卡（termcard）

把"知道名字"换成"知道机制"。术语是压缩码，不是解压后的内容——本 skill 负责解压。

## 何时用

用户问某个术语/概念"是什么意思、本质是什么、为什么叫这个"，或抱怨"被名词绕晕了、别用术语"时。
显式调用：`/termcard <术语>`。

## 第一步：分类

先判定术语类型（一词可多类，声明当前语境）：

| 类型 | 特征 | 例 |
|---|---|---|
| 隐喻型 | 名字带比喻，比喻被过度延伸 | attention、温度、幻觉、背驰 |
| 标签型 | 名字任意无信息量；或一词两制（同名不同物） | LSTM、群、因子 |
| 缩写/人名型 | 缩写或以人命名 | GRU、傅里叶变换 |
| 造物嫌疑型 | 名下可能无统一机制 | 涌现、智能、风口 |

## 第二步：按类出牌

- **隐喻型**：拆比喻，明确指出比喻在哪里失效
- **标签型**：跳过名字直接讲结构；一词两制的拆成两条机制分开讲
- **缩写/人名型**：一句话交代来历，立刻转机制
- **造物嫌疑型**：列出该词实际涵盖的几种机制，逐条替换验证，允许结论是"名下无物"

## 第三步：输出五格卡

```
【机制】它实际是什么
【来历】为什么恰好叫这个
【误导】名字把人带向哪里
【重建】忘掉名字，从问题出发重新走到它
【边界】解构后仍然消不掉的复杂度
```

各格写作规范：

- **机制**：只能用更基础的词描述（数学原语、日常经验、可运行例子）。锚不定的基础词递归解构，解到能锚定为止。优先级：可运行的例子 > 数学结构 > 类比；类比必须标注失效点
- **来历**：通常是历史偶然，交代清楚即可，不展开
- **误导**：写出名字导致的**具体错误推论**，不写"可能让人误解"这种空话
- **重建**：假如名字不存在，从什么问题出发会自然重新发明这个机制。达不到"没有这个词也能懂"就重写
- **边界**：严格区分两种复杂度——命名造成的伪复杂度（可消除）vs 领域的本质复杂度（消不掉）。后者明说"这步逃不掉"

## 质量红线

1. **禁止廉价简化**：边界栏必须有实质内容；如果整个领域都是硬的，直说
2. 解构给出的"机制"也是叙述不是真理——锚定基础词汇是唯一的约束手段，不引入新的权威名词
3. 同一词在不同领域类型可能不同（"熵"在信息论是标签型，在科普文里常被隐喻滥用），解构前声明语境
4. 解构用词如果本身也是术语，要么换掉，要么顺带一格 mini 卡

## 累积

每次解构后，把卡片追加到 `~/.claude/termcard/terms/<领域>.md`（如 `ai.md`、`quant.md`）。目录不存在则创建。
**缓存不是依赖**：miss 照样现场解构，任何生僻领域不降级。
同域再遇术语时，已解构过的基础词直接引用，不重做。库越厚，解释越快。
单领域长期使用中纠错优先级最高：读者纠错当场改卡，错误卡片被反复引用会放大扎根。

范例见 `examples.md`（三张已验证的卡：幻觉/因子/涌现）。
