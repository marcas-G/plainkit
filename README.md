# plainkit —— 说人话工具箱

把任何专业内容，翻译到你已有的语义空间。

## 问题

命名概念会成为理解一个领域的障碍——本质的道理并不复杂，但大多数人被名字困住了。术语之害有三种：

1. **空指针**——知道名字，不知道机制，但以为自己懂了。术语是压缩码，新手把 zip 文件名当成了解压后的内容。
2. **隐喻过载**——名字带了个比喻，比喻被过度延伸。"Attention"让人以为模型在"注意"，本质是可微的加权混合；"温度"与热无关，是 logits 除以一个数。
3. **命名造物**——起了名字，人们就开始找它的"本质"，仿佛它存在。"涌现"名下可能同时塞着真实机制、度量假象和纯修辞。

## 两个 skill

### plain —— 下译翻译器

**内核：在读者已有的语义空间里，重建原文的因果结构；重建不了的部分诚实标出。**

三个不变量约束一切规则：

| 不变量 | 内容 |
|---|---|
| 结构不变 | 被译对象是因果/运算结构，不是词、不是形象 |
| 空间锚定 | 译文必须落在读者已有空间（生活常识 / 系统机制 / 数学原语），落不进的就是显式"新构造" |
| 诚实边界 | 区分语言复杂度（可消）与结构复杂度（不可消），不可译处明说，禁止硬类比 |

三种模式：

- **说人话**（默认）——任何拽词内容译到生活常识层。格式跟随原文（叙述对叙述、清单对清单），分析脚手架不外露
- **领域桥**——"用我懂的领域给我讲 X"。产出四件套：机制地图 / 翻译表（同构·部分对应·仅类比三档强度）/ 不可译清单（真门槛所在）/ 攻击顺序
- **术语深解**——调 termcard 出五格卡

长期外挂设计：维护三个状态文件（读者画像 / 译名锁定表 / 领域卡库），逐词毕业机制让翻译随你的成长自动收敛。

### termcard —— 术语卡

单术语五格解构：**机制**（它实际是什么）/ **来历**（为什么恰好叫这个）/ **误导**（名字导致的具体错误推论）/ **重建**（忘掉名字，从问题出发重新走到它）/ **边界**（解构后仍消不掉的复杂度）。

先分类再出牌：隐喻型（拆比喻）/ 标签型（跳过名字讲结构）/ 缩写人名型（一句话来历转机制）/ 造物嫌疑型（列出名下实际机制，允许结论是"名下无物"）。

## 安装

```bash
# 从 GitHub
/plugin install marcas-G/plainkit

# 或本地路径
/plugin install /path/to/plainkit
```

## 状态文件（升级不丢，个人积累与代码分离）

读者的个人状态存在 `~/.claude/plain/` 与 `~/.claude/termcard/`，插件升级不覆盖：

```
~/.claude/plain/
├── user-space.md   # 读者空间画像：你熟什么，母领域是什么
├── canonical.md    # 译名锁定表：同一概念固定译法，防漂移
└── terms/          # 领域卡库：打过的机制骨架与验证过的翻译

~/.claude/termcard/terms/   # 术语卡积累
```

首次使用自动初始化（画像从对话推断并声明假设，你可随时纠正）。

建议：把自己的状态目录 `git init` 一下——你的读者画像和卡库是个人知识资产，值得版本化。

## 使用示例

```
"这段研报到底在说什么"          → 说人话（长文三步走）
"用我懂量化的方式讲讲免疫学"     → 领域桥（对照表四件套）
"'凸性'这词什么意思"           → termcard 五格卡
"负反馈不是稳定器吗？"          → 结构映射顺带质检原文用词
```

## 设计原则

- **方法论，不是字典**——生活常识是场景空间不是词表空间，翻译靠现场生成；卡库只是缓存，miss 不降级，任何生僻领域照常分析
- **零领域预设**——不内置领域清单，目标领域和母领域都是运行时参数
- **读者空间内的话不译**——译只发生在跨界处；你毕业后它闭嘴
- **反权威**——翻译给出的"机制"也是叙述不是真理，锚定基础层是唯一约束；发现原文用词错误（如市场文本说"负反馈"实为正反馈）当场指出
- **终极目标是让你不再需要它**
